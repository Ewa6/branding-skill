# Finish the brand book in Codex

Build the final book from accepted decisions and actual assets. It is a usable standard for the next designer/writer, not a collage of experiments. Resolve essential choices or label the book as a working edition with explicit limitations.

Copy [brand-book.html](../assets/brand-book.html) to `brand/brand-book/index.html` and [tokens.css](../assets/tokens.css) to `brand/tokens.css` unless the project already has a canonical token source. The starter's `../tokens.css` link assumes that output layout. Restyle it to this brand; do not retain demonstration values or empty sections. A responsive long page and reviewed PDF export are the default portable formats. The brand book can span multiple print pages.

## Content

Adapt sections to scope:
- Brand essence: purpose, audience, positioning, credible promise and personality.
- Verbal identity: messages, tagline status, voice, examples, vocabulary and tone shifts.
- Logo: actual master/variants, clear space, minimum sizes, background rules and misuse.
- Palette: named roles, exact values, permitted contrast pairs, print/monochrome use if relevant.
- Typography: actual families, source/licence, weights, scale, language coverage and examples.
- Graphic system: signature components, icons and picture style; theme/configuration rules if applicable.
- In use: relevant finished screen/print/context examples, including hard states.
- Production: formats, practical constraints, remaining external checks.
- Downloads, asset inventory, licences, version and exact approval status.

Include only applicable chapters. Cross-link the full voice guide and component/source files. Make visual examples concrete. “Do not stretch” can be shown next to the correct lockup; distinguish misuse illustrations from approved logo variants.

## Build and verify

Use canonical tokens and permitted local fonts/assets. Prefer relative links and no required CDN/network access. Brand typography and precise copy should be live text in the book, not screenshot-only labels.

Use accessible headings, meaningful alt text, sensible contrast and responsive grids. Test a phone width and desktop, missing network, anchor/download links and actual font loading. Allow long words/tables to wrap without horizontal page overflow.

Export a PDF, render and inspect each page. Fix broken tables, orphan headings, cropped assets, unreadable type and wasteful breaks. Use the available PDF/document skill as applicable; a successful browser export alone does not establish layout quality.

Check the HTML and PDF against the same decisions and asset versions. Remove scaffolding, alternatives and obsolete prompts from the final standard. Capture the final owner's approval only to the extent it was actually supplied; delegated design choices should be identified as such.

Link the book and curated local ZIP. Upload or publish only when authorized; a local reviewed artifact is a complete delivery without hosting.
