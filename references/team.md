# A small team that changes the work

Use independent agents for substantial choices when available and permitted. This skill supports delegation for design and review; it does not require a large team for every step. Respect the runtime's active-agent limit. The lead can also make work, verify it and write the report.

## Roles

| Role | Contribution |
| --- | --- |
| Lead / orchestrator | Writes the shared brief and scope, integrates changes, keeps decisions current and delivers |
| Art director / maker | Builds a coherent system; proposes specific composition, type and component changes |
| Design challenger | Independently contests assumptions, visual claims and unnecessary complexity using the actual work |
| Verifier | Checks facts, source fidelity, geometry, file formats, font loading and contrast evidence |
| Simulated viewer, optional | Reads artifacts from a stated use context and reports immediate confusions; explicitly AI role-play |
| Additional maker, optional | Explores a meaningfully different direction when alternatives are needed |

For naming, two or three distinct maker registers plus an independent checker can help. Schedule roles in waves rather than trying to launch seven agents simultaneously. Reporter is usually the lead, not a separate permanent agent.

## Challenger brief

Give the challenger the owner's actual words, current source references, artifact paths and intended use. Ask:
1. What do we claim this achieves, and what in the visible result supports or contradicts that?
2. Does it preserve approved components and hard constraints?
3. Is there an unresolved reading-order, hierarchy, density, semantic or physical problem?
4. What smallest concrete change would improve it? What should remain untouched?
5. Is the proposed scope expanding product mechanics or approval?

For rebranding, also ask which changes address the stated problem, what useful recognition is retained or lost, and whether the team is defending the old identity or adding novelty without evidence. Assess the agreed depth of change; a complete redesign is not a failed preservation exercise.

The challenger is not a contrarian persona and does not invent a problem to justify its role. “No actionable issue” is valid. It cannot overrule owner taste with an AI majority. Distinguish observed defects, design preference and unverified hypotheses.

Useful NieZamulaj challenges: repeated completion text made the full board administrative; a reward had an awkward orphan word; dinosaur plates read as a crown; an offline message assumed an existing printed board. Each led to a concrete correction. Do not repeat the failed treatments as suggested brand elements.

## Round contract

Before dispatch, record the question, approved inputs, fixed constraints, requested files, owner exclusions and what counts as enough evidence. Give each agent a separate output area or use read-only review; the lead owns shared files.

Use one making pass, an independent critique of actual renders, then a focused correction pass. Recheck changed outputs and any affected constraints. Keep disagreement that matters visible. Stop when issues are resolved or an external fact/owner choice is needed; do not regenerate for consensus.

Do not run unbounded debate, redundant lookups or repeated image batches. Choose batch size proportionate to the decision and tool budget (often two or three alternatives, not dozens). User-directed iterations remain possible. After repeated tool failures, mark the check unverified and continue unaffected work. Do not encode a one-off hourly lookup quota as a universal rule.

## Review notes

Save concise evidence: artifact/version reviewed, role, finding, proposed change, lead response and result. Peer agreement is neither owner approval nor real-world validation. If agents cannot view the output, label the review as source-only; a text description is not a visual inspection.

A single agent can perform separate making and critique passes when delegation is unavailable. Call this self-review rather than independent verification.
